総合検査フェーズ仕様（仮）
============================

位置づけ
--------
既存の魔法インデックスに個別登録されている探査・走査系魔法を「総合検査」へ統合する。

総合検査を実行すると、現在の問診画面とは別に用意した総合検査専用シーンへ移る。
検査シーンでは、患者の同じ身体位置を「目視」「非破壊内部検査」「読心」の3モードから比較して観察する。

検査によって直接診断名や正解を表示するのではなく、プレイヤー自身が客観所見と主観症状を集め、問診や別検査の結果と照合する。


MPの役割
--------
MPは、魔法を使用するための資源と、検査中に集中を維持するための疑似的な集中力を兼ねる。

現時点で検討中の消費量は次の通り。

- 総合検査シーンへの遷移：20 MP
- 使用する検査魔法の変更：1回につき2 MP
- 目視・非破壊内部検査中の時間経過：1秒につき0.1 MP
- 読心中の時間経過：1秒につき1 MP

上記の数値は仮決定であり、実際の操作時間と難易度を確認して調整する。

初期状態は目視とし、シーンへ入った直後の目視選択には、入場費用以外の魔法変更費用を追加しない。

同じ検査魔法を再度選択した場合も、魔法変更とはみなさずMPを消費しない。

時間経過によるMP消費は、総合検査シーンで実際に検査を行っている間だけ発生する。検査終了後、元の問診画面へ戻った時点で停止する。

MPが不足している場合の最終的な挙動は未決定。仮実装では、次の扱いを候補とする。

- 入場時に20 MP未満ならシーンへ移動せず「MPが足りません。」と表示する。
- モード変更時に2 MP未満なら、現在のモードを維持して変更しない。
- 検査中にMPが0になった場合は、新しい操作を停止して検査終了を促す。


シーン構成
----------
新規シーン名の仮称を「ComprehensiveExaminationScene」とする。

仮実装では、現在の問診シーンを保持したまま検査シーンを加算ロードする方式を想定する。
これにより、次の状態を破棄せず検査へ移れる。

- 会話ログ
- 出力済み会話ノード
- 問診の進行状況
- 現在MP
- 発見済み所見

総合検査中は問診側のCanvasを非表示または操作不能にする。
「検査終了」を押すと検査シーンをアンロードし、問診画面へ戻る。


魔法インデックス
----------------
魔法インデックスには、探査魔法を代表する項目として「総合検査」を1件表示する。

現時点で統合候補となる既存魔法は次の通り。

- スキャン魔法
- 視覚強化魔法
- 超音波
- CT
- レントゲン
- MRI（雷魔法＝磁場）
- MRI魔力版
- 神経系走査
- 生体電気確認

これらを個別の魔法ボタンとして残すのではなく、総合検査シーン内の観測機能へ統合する。

血液検査、毒性解析、分子解析は、身体をその場で観察する総合検査とは性質が異なるため、当面は別検査として魔法インデックスに残す。


画面構成
--------
画面を左、中央、右の3列として扱い、中央約1/3の領域を人体模型に使用する。

左側は、画面左上から下方向へ次の順番で並べる。

1. 患者の顔写真または顔イラスト
2. 心拍表示
3. 苦痛グラフ
4. 判明した情報の列挙欄
5. 診断シーンへのリターンボタン

左側UIは、診断シーンへのリターンボタンを除いて垂直ScrollRect内へ配置する。
スクロール内容は、上から患者の顔、心拍グラフ、苦痛グラフ、判明した情報の順とする。
リターンボタンは左下へ固定し、スクロールしても移動しない。

心拍グラフと苦痛グラフは、スクロールContent内でそれぞれ独立したRectTransform土台を持つ。
以前の固定配置`(0, 0.5)～(0.33, 0.75)`および`(0, 0.25)～(0.33, 0.5)`は、垂直スクロール化に伴って固定画面座標としては使用しない。

患者の顔表示は、患者の表情や苦痛の変化を視覚的に伝えるために使用する。

心拍表示と苦痛グラフは別の情報として扱う。
心拍表示は生理的な心拍情報、苦痛グラフは読心によって観測した主観的苦痛の時間変化を表す。

判明した情報の列挙欄には、目視、非破壊内部検査、読心、その他の検査で発見した所見を表示する。

リターンボタンの画面上の表示名は仮に「診断へ戻る」とする。
このボタンを押すと総合検査を終了し、元の診断・問診シーンへ戻る。

中央約1/3には人体模型を配置する。
人体模型は、次の6領域をそれぞれ角丸矩形で表現する。

1. 頭部
2. 胴
3. 左腕
4. 右腕
5. 左足
6. 右足

各領域は独立した判定範囲を持つ。
仮実装では正確な人体の輪郭を作らず、6個の角丸矩形を人体に見える位置関係で配置する。

右側は、画面右上から下方向へ次の順番で並べる。

1. 現在レイヤー表示
2. 現在MP表示
3. カルテ表示またはカルテボタン
4. 検査魔法選択メニュー

従来モード切り替えとしていた操作は、使用する検査魔法の選択として扱う。
選択肢は「目視」「非破壊内部検査」「読心」とし、選択中の検査魔法によって画面の観測モードを切り替える。
画面下側に配置する場合は、選択肢が画面外へはみ出さないよう上方向へ開くプルアップ形式とする。

人体模型と虫眼鏡の位置は、モードを切り替えても維持する。
これにより、同じ身体領域を3種類の観測方法で比較できるようにする。


検査魔法と選択可能レイヤー
--------------------------
各検査魔法は、それぞれ選択可能なレイヤー一覧を持つ。
現在選択中の検査魔法に対応していないレイヤーは、レイヤー選択欄に表示せず選択できないようにする。

仮実装での対応関係は次の通り。

- 目視
  - 身体表面
- 非破壊内部検査
  - 表皮・皮下
  - 神経
  - 血管
  - 筋肉
  - 骨
  - 内臓
- 読心
  - 主観症状

各検査魔法のレイヤー一覧は、最も表層側から深部側の順に保持する。

検査魔法を切り替えた際、現在のレイヤーが切り替え先でも選択可能なら、そのレイヤーを維持する。
現在のレイヤーが切り替え先に対応していない場合は、切り替え先のレイヤー一覧で最も表層側にあるレイヤーへ自動的に切り替える。

例は次の通り。

- 目視から非破壊内部検査へ変更：身体表面は対象外なので「表皮・皮下」へ切り替える。
- 非破壊内部検査の内臓から読心へ変更：内臓は対象外なので「主観症状」へ切り替える。
- 読心から目視へ変更：主観症状は対象外なので「身体表面」へ切り替える。

レイヤーの自動切り替えによる追加MP消費は発生しない。
2 MPを消費するのは、選択中の検査魔法そのものが変更されたときだけとする。


共通操作
--------
- マウスまたはタッチ操作で虫眼鏡を移動する。
- 目視と非破壊内部検査では、虫眼鏡の円形範囲内だけ詳細情報を表示する。
- 読心では、虫眼鏡の位置にかかわらず対応する主観症状の患部を表示する。
- 所見の判定範囲に一定時間とどまると、その所見を発見する。
- 発見済み所見は一覧へ記録し、同じ所見を重複取得しない。
- 発見時には、診断名ではなく観測した事実を短い文章で表示する。
- 検査終了後も発見済み状態を保持する。


患部表示と発見進行
------------------
患部の位置は、LineRendererで描画した閉じた32角形の輪郭として表現する。

- 頂点数は32とする。
- LineRendererの始点と終点をつなぎ、閉じた図形として表示する。
- 線の色は赤とする。
- 初期状態の透明度は完全透明、すなわちアルファ値0とする。
- 目視と非破壊内部検査では、現在の検査魔法とレイヤーが患部に対応し、虫眼鏡が接触している場合だけ接触時間を加算する。
- 読心では、主観症状レイヤーを選択している間、虫眼鏡との接触にかかわらず発見進行時間を加算する。
- 虫眼鏡の対象範囲が患部の判定範囲へ接触している間、接触時間に応じて赤線を徐々に不透明にする。
- 虫眼鏡が離れた場合、それまでに上昇した透明度と累積接触時間は保持する。
- 必要接触時間へ達した時点で患部を発見済みとする。
- 発見後は、その患部に設定された最大不透明度を維持する。

表示の進行度は、次の考え方で求める。

発見進行度 ＝ 累積接触時間 ÷ 発見に必要な接触時間

発見進行度は0から1の範囲に制限し、LineRendererのアルファ値を、完全透明から患部ごとの最大不透明度まで補間する。

異なる検査魔法または対応外レイヤーを選択している間は、接触時間を加算せず患部表示も進行させない。

LineRendererで描画するのは32角形の輪郭であり、図形内部の塗りつぶしではない。
将来、患部全体を半透明の赤で塗りつぶす場合は、Meshまたは専用のUI Graphicを別途使用する。

表示中の患部は、半径0から患部ごとの最大半径まで一定速度で拡大する。
最大半径へ達した直後、半径を瞬間的に0へ戻し、再び拡大を開始する鋸歯状アニメーションを繰り返す。
仮実装の1周期は1秒とし、Inspectorの`lesionSawtoothPeriodSeconds`から調整可能とする。
各時点の表示半径は次の式で求める。

```
位相 = Repeat(経過時間 ÷ 周期, 1)
表示半径 = 患部の最大半径 × 位相
```

このアニメーションは表示だけに適用し、虫眼鏡との接触判定には患部本来の最大半径を使用する。
透明度、発見進行度、発見済み状態には影響させない。


目視モード
----------
患者の身体を外側から観察するモード。
魔法的な内部透視を行わず、通常の視認または視覚補助によって確認可能な情報だけを表示する。

主な対象は次の通り。

- 傷
- 発赤
- 腫れ
- 体色の変化
- 発疹
- 分泌物
- 露出した異物
- 外見上の左右差

Stage01では、左手の浅い切創や周辺の発赤を発見できる。
皮内に完全に埋まった異物、低血糖、内臓の異常などは目視だけでは確認できない。


非破壊内部検査モード
--------------------
患者の身体を傷つけず、内部構造を観察するモード。

内部表示は、次の身体レイヤーを扱える構造とする。

- 表皮・皮下
- 神経
- 血管
- 筋肉
- 骨
- 内臓

仮実装では、深度またはレイヤーを切り替えて観察する。
超音波、CT、レントゲン、MRIなどの個別名称は、最初から別モードに分割せず、このモードに統合する。

将来必要になった場合は、非破壊内部検査モード内の観測方式または表示フィルターとして個別化できる。

Stage01では、次のような所見を発見できる。

- 切創部直下に残る白い針状異物
- 異物周囲の炎症
- 異物から血中へ拡散する異常反応
- 肝臓周辺の代謝異常

表示する文章は「毒草中毒」などの診断名ではなく、「左手皮下に白い針状構造を確認」のような観測事実とする。


読心モード
----------
身体構造ではなく、患者本人が感じている主観症状を観測するモード。

主な対象は次の通り。

- 痛み
- しびれ
- 灼熱感
- 倦怠感
- 吐き気
- 渇き
- 息苦しさ
- 空腹感

局在する症状は患者模型上の色付き領域として表示する。
倦怠感のような局在しにくい症状は、患者模型全体への薄い色などで表現する。

読心による位置情報は患者の主観であり、原因部位と一致するとは限らない。
放散痛は、原因部位とは異なる場所へ痛みを表示するジャミングとして利用できる。

読心モードでは、虫眼鏡の位置にかかわらず、対応する主観症状の患部を最大不透明度で表示する。
未発見の主観症状は、読心モードを継続している時間によって自動的に発見進行し、必要時間へ達すると判明した情報へ追加する。
広範囲を一度に観測できる代わりに、読心モード中の維持消費は1 MP/秒とする。
目視および非破壊内部検査中の維持消費は0.1 MP/秒のままとする。


痛みの反応波形
----------------
読心モードでは、心電図とは別物として「痛みの反応波形」を表示する。

- 波形の基線：持続的な苦痛の強さ
- 波形の振幅：苦痛の揺れ
- 波形の速さ：苦痛反応の頻度

心拍そのものと誤解されないよう、画面上では「痛み反応」などの名称を明記する。

仮実装では患者から数値を実測せず、症例データに設定した値をもとに波形を生成する。

MPは魔法コストおよび疑似的な集中力であると同時に、症例内の疑似経過時間として扱う。
各ステージは、現在MPを入力とする次の3本の関数を持つ。

- 心拍数 = f(MP)
- 苦痛度 = f(MP)
- 苦痛度ばらつき = f(MP)

実装では3本をAnimationCurveとして症例データに保持する。
横軸は現在MPであり、MPが消費されるため、検査中はカーブをMPの高い側から低い側へたどる。
目視・非破壊内部検査中の毎秒0.1 MP、読心中の毎秒1 MPの維持消費だけでなく、検査開始時の20 MPと検査魔法切り替え時の2 MPも、MP減少後の値から各関数を再評価する。

苦痛度は0～10の基線、苦痛度ばらつきは0～10の最大振幅として扱う。
苦痛グラフは、`苦痛度=f(MP)`を基線、`苦痛度ばらつき=f(MP)`を波形の振幅として生成する。
心拍グラフの拍動間隔は、`心拍数=f(MP)`で得たbpmから算出する。
心拍グラフは0を平常値、10を拍動時の値とするパルス波形で表示する。
1拍を8サンプルで表現し、`10, -3, 1, 0, 0, 0, 0, 0`を1周期とする。
心拍のサンプリング間隔は固定値ではなく、次の式で現在の心拍数から計算する。

```
心拍サンプリング間隔（秒） = 60 ÷ 心拍数 ÷ 8
```

心拍グラフのfloat配列長は心拍数にかかわらず80で固定する。
したがって、心拍グラフには常に約10拍分のパルスが保持される。
苦痛グラフは心拍のサンプリングレートへ連動させず、0.15秒間隔を維持する。

ステージ別の具体的なカーブが未設定の場合は、中立値として心拍数88 bpm、苦痛度5、苦痛度ばらつき2を使用する。

各ステージは、MPが0になった際のポリシーとして`Stable`または`Fatal`を持つ。

- Stable：各生体値は`f(0)`の値を維持する。非致死症例の既定動作とする。
- Fatal：MPが0になった瞬間に心拍数を0とし、苦痛度を`N/A`、苦痛度ばらつきを0とする。苦痛グラフは非表示にする。

Stage0のMP 0ポリシーは`Fatal`とする。

波形描画にはLineRendererと長さ80のfloat配列を使用する。
配列はリングバッファとして扱い、先頭アドレス用の整数`initialAddress`と、描画時の参照アドレス用整数`address`を持つ。

新しい値を書き込むたびに`initialAddress`を1つ進め、80で剰余を取る。
描画時は次の形で古い値から順番に80点をLineRendererへ設定する。

```
for (int i = 0; i < 80; i++)
{
    address = (initialAddress + i) % 80;
    lineRenderer.SetPosition(i, new Vector3(100f + i * 5f, samples[address], 0f));
}
```

LineRendererの描画結果はRenderTextureへ出力し、左側の苦痛グラフ欄へ表示する。
心拍グラフにも同じ長さ80のfloatリングバッファ、アドレス計算、LineRenderer描画方式を使用する。
心拍と苦痛は、それぞれ独立した配列、先頭アドレス、LineRenderer、RenderTextureを持つ。
心拍グラフと苦痛グラフのLineRenderer線幅は0.2とする。
80点を従来と同じ表示幅へ収めるため、グラフの横方向だけを圧縮して表示する。


3モードの比較
-------------
同じ身体位置でも、選択したモードによって異なる情報を得る。

例：Stage01の左手

- 目視：複数の浅い切創と発赤
- 非破壊内部検査：皮内の白い針状異物
- 読心：灼熱感と指先のしびれ

この比較を、総合検査フェーズの中心的な操作とする。


検査結果と診断
--------------
総合検査は万能診断器にしない。
総合検査で得られるのは、身体の外見、内部構造、患者の主観症状に関する所見である。

血液の数値や分子構造などは、引き続き別検査を必要とする。

Stage01では、次の情報を組み合わせる。

- 総合検査：切創、皮内異物、症状の分布
- 血液検査：低血糖
- 毒性解析または分子解析：脂質代謝を阻害する構造
- 問診：薬草採取時に手を切ったという経緯

必要な情報が揃った時点で、既存の自動推論へ接続する。


Stage01用の仮所見
-----------------
- S01-V001：目視／左手の浅い切創
- S01-V002：目視／切創周辺の発赤
- S01-I001：非破壊内部検査／皮内の白い針状異物
- S01-I002：非破壊内部検査／異物から血中へ拡散する反応
- S01-M001：読心／左手の灼熱感
- S01-M002：読心／指先のしびれ
- S01-M003：読心／全身の脱力感と異常な空腹感


所見データ
----------
症例ごとの所見には、少なくとも次の情報を持たせる。

- 所見ID
- 表示名
- 説明文
- 必要な検査魔法
- 身体部位
- 身体レイヤー
- 身体上の位置
- 判定範囲
- 発見に必要な観察時間
- 累積接触時間
- LineRendererの32頂点位置または患部形状を生成するための値
- 発見後の最大不透明度
- 線幅
- 表示色
- 前提所見
- 会話側へ通知するイベントID

検査魔法は次の3種類とする。

- Visual：目視
- Internal：非破壊内部検査
- Mental：読心

各検査魔法は、表層側から順序づけた選択可能レイヤー一覧を持つ。

発見済み所見は検査魔法を変更しても消去せず、症例全体の進行状態として保持する。


既存会話システムとの接続
------------------------
現在の「スキャン魔法を入力すると、切創と異物が文章で同時に判明する」処理は、総合検査へ置き換える。

想定する流れは次の通り。

総合検査を選択
→20 MPを消費
→検査シーンへ移動
→目視で切創を発見
→非破壊内部検査で異物を発見
→発見結果を会話側へ通知
→検査終了後に問診画面へ戻る

総合検査を選択しただけでは検査結果を出さない。
何も発見せずに戻った場合も、会話ログへ「？」を出さない。

会話ノードIDと検査所見IDは直接混在させず、検査側で発見済み所見IDを管理し、接続処理を通じて対応する会話ノードや自動推論を解禁する。


仮実装の完成条件
----------------
- 魔法インデックスに「総合検査」が1件表示される。
- 総合検査の開始時に20 MPを消費する。
- 新規の総合検査シーンへ移動できる。
- 目視、非破壊内部検査、読心の3種類から使用する検査魔法を選択できる。
- 使用する検査魔法を実際に変更するたびに2 MPを消費する。
- 選択中の検査魔法に対応するレイヤーだけを選択できる。
- 魔法切り替え時に現在レイヤーが対象外なら、切り替え先の最も表層側のレイヤーへ自動変更される。
- レイヤーの自動変更では追加MPを消費しない。
- 目視・非破壊内部検査中は毎秒0.1 MP、読心中は毎秒1 MPを消費する。

- 患部が赤いLineRendererの閉じた32角形として用意されている。

- 患部は初期状態では完全に透明である。
- 対応する検査魔法とレイヤーで虫眼鏡を接触させると、累積接触時間に応じて患部が徐々に不透明になる。
- 虫眼鏡を離しても、患部の発見進行度が保持される。
- 読心では虫眼鏡の位置にかかわらず主観症状の患部が表示され、発見進行が自動的に加算される。
- 各検査魔法に1個以上の所見が配置されている。
- 発見済み所見を一覧表示できる。
- 検査終了後も発見状態と残りMPが保持される。
- 元の問診画面へ戻れる。
- 発見内容を既存の推論条件へ反映できる。

- 目視、非破壊内部検査、読心の切り替え時に2 MPを消費する。
- 検査魔法ごとに選択可能レイヤーを制限し、対象外レイヤーから切り替えた場合は最も表層側へ自動補正する。
- 画面中央に頭部、胴、両腕、両足の6個の角丸矩形を配置する。
- 左側へ患者の顔仮表示、心拍、苦痛グラフ、判明情報、診断へのリターンボタンを配置する。
- 苦痛グラフを80要素のfloatリングバッファとLineRendererで描画し、RenderTexture経由でUIへ表示する。
- 心拍グラフにも同じ80要素リングバッファとLineRenderer描画を適用した。
- 心拍グラフを`10, -3, 1, 0, 0, 0, 0, 0`のパルス波形とし、配列長80を維持したまま、サンプリング間隔を`60 ÷ 心拍数 ÷ 8`で動的に計算するようにした。
- 心拍と苦痛のグラフ線幅を0.2とし、80点を同じ表示幅へ収める横方向圧縮を適用した。
- MPを疑似経過時間として扱い、ステージごとに心拍数、苦痛度、苦痛度ばらつきをそれぞれ`f(MP)`のAnimationCurveで指定できるデータ構造を追加した。
- 左側UIを垂直ScrollRect化し、患者の顔、心拍グラフ、苦痛グラフ、判明情報をスクロールContentへ移した。
- 診断へのリターンボタンは左下へ固定し、スクロール対象外とした。
- 右側へ現在レイヤー、MP、カルテ仮ボタン、検査魔法のプルアップメニューを配置する。
- 虫眼鏡の対象範囲を32角形で表示する。
- Stage01用に目視、非破壊内部検査、読心の患部を各1件仮配置した。
- 患部を赤いLineRendererの閉じた32角形とし、正しい魔法とレイヤーでの累積接触時間に応じて不透明化する。
- 読心中は虫眼鏡にかかわらず主観症状の患部を最大不透明度で表示し、発見進行を自動加算する。
- 患部表示へ1秒周期の鋸歯状半径アニメーションを追加し、接触判定半径とは分離した。
